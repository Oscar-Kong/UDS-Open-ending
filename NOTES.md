# Requirements

- Survey item: "Do you feel Northeastern students have any advantages over non-Northeastern peers? Please explain?"
- Grounded answers only. Hard filter stays in front of any model. Do not fine-tune. Do not send every row to a generative model.
- Race and gender stay off the UI and are not loaded into Record.
- Campus is unreliable before 2023.
- Server is 127.0.0.1:8787. Do not kill unrelated pid 65860 on 8765.
- Do not commit unless asked. Do not print API keys. .env is gitignored.
- A key saved in Library (data/model.json) overrides .env.
- App is stdlib Python only. UI is vanilla HTML/CSS/JS.
- Northeastern brand: black #000000, white #FFFFFF, red #C8102E under about 25%, canvas #F6F6F4, subtle #3A3A3A, border #D9D9D6. Lato. Sharp 2px corners. No shadows. SVG icons. 44px targets. Focus rings. prefers-reduced-motion.
- LLM settings names: LLM_API_KEY, LLM_BASE_URL, LLM_MODEL. UI labels: LLM key, Endpoint, LLM name. Dash base https://api-llm.dashlab.studio/v1, model gemma4:31b (the host does not serve gemma4:latest), think false.
- Each answer shows Scope, Stance, and Reasons as a small table in a narrow rail on the left as soon as the question is asked. The summary, chart, and quotations use the remaining width beside that rail. Evidence is one line under the summary. Accuracy panel checks numbers, quotations, and the refusal line.
- Insufficient support hides the reason ranking. Fallback paragraph is the grounded headline when the LLM fails.
- A count, comparison, or reason-ranking question also shows a small chart or table from those counts. A question the comments cannot answer, or a slice with insufficient support, has no chart.
- The opening screen greets Northeastern faculty by time of day (Good morning, Good afternoon, or Good evening), then lists nine sample questions in three groups: Bar chart, Table, and No chart.
- The sidebar stays fixed while an answer scrolls. Only the history list scrolls when there are many chats. A new answer writes the summary a few words at a time, then shows quotations and the accuracy checks. Reduced motion shows the full answer at once.
- Ask one slice at a time. Parser colleges: Khoury / computer science / ccis, engineering, business school / damore / mckim (not the word business alone), Bouve, college of science, cssh / social sciences, camd / arts media, cps / professional studies, law school / law students. Levels: undergraduate, graduate, law. Years 2016–2026. Period compare needs the word changed and a year.
- The chat box has a Model menu. Names come from GET /models on the saved endpoint. If that list fails, the menu shows the last list saved on this machine, or for Dash the recorded names gemma4:31b, nemotron3:33b, and qwen3.8:27b. The choice is sent with the question and stored on that chat. data/chats.json, data/evals.json, and data/models.json are gitignored.
- Chat history is saved in data/chats.json and listed in the sidebar. New chat keeps the previous thread. Delete removes that record. The list keeps the 50 most recent chats. After the first answer is saved, one short model prompt writes a 4-to-7-word title. If that call fails it is tried once more, then the title stays the question. A failed answer call is also tried once more before the filtered summary is shown.
- Evaluation tab follows UK AISI Inspect (https://inspect.aisi.org.uk/eval-logs.html): the same six questions, solver pipeline.chat.reply, scorers numbers / quotations / slice, values C and I. A failed model call is incorrect. Runs are saved in data/evals.json, 20 most recent. Up to four models per run. Filtered counts can sit in the same table.
